# SRC-1201: sequencer payload byte budget

The user approved a production-only byte limit on 2026-11-11. Both repositories use `fix-bounty-1201`, based on their respective `develop` branches.

## Behavior

Optimism block production with txpool filling gets a transaction byte budget of `8*1024*1024 - 1_000_000` bytes. All successfully included transactions consume the same budget, including forced attributes, deposits, bundles and DAG transactions. Check the budget before executing a transaction; rejected transactions must not change state, gas or size accounting. Copy both accounting fields when copying the mining environment for MEV fallback. A transaction which does not fit is skipped together with its sender's nonce successors; other senders can still fill the block. Bundle inclusion failure uses the existing independent txpool fallback.

An oversized forced prefix must produce an error, never a silently truncated prefix. Validate its size synchronously before starting background payload construction. `NoTxPool=true` is also used for historical derivation, so it retains its existing semantics. Ethereum mining, block import, gas accounting, hard-fork configuration and historical validation are unchanged.

The one-million-byte margin accommodates RLP/SSZ framing, headers and auxiliary fields. Do not increase the gossip or channel limits: doing so in isolation cannot solve both constraints. No new consensus rule or activation timestamp is introduced.

## Verification

First reproduce the report's 100 transactions with 130,000 zero bytes each and a 100M gas limit. The regression expects a nonempty, truncated block within the budget. Test forced-prefix rejection, mixed forced/pool accounting, bundle inclusion, environment copying, failed transaction accounting, and unrestricted historical reconstruction. Test downstream signed SSZ gossip and both singular/span batch channel encodings at the producer budget, retaining rejection tests for the original 13 MB case.

## Limits

This prevents public txpool traffic from producing the reported oversized canonical block after the sequencer is upgraded. It does not recover a previously produced oversized block, impose a consensus limit on historical blocks, or constrain a trusted caller explicitly requesting historical reconstruction with `NoTxPool=true`.
